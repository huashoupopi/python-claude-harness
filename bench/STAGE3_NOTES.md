## 一、TODO 轴：复现，并且拿到了剂量-反应关系

```
关掉 todo 之后的步数变化          配对结果（同题同 trial 跨臂比）
  老 8 题        -5.3 步          0↑ / 21↓ / 3平
  新 4 题        -8.5 步          0↑ / 12↓ / 0平
  新 3 题(多轮) -12.1 步          0↑ /  9↓ / 0平
                                 ──────────────
                       合计       0↑ / 42↓ / 3平
```

**42 比 0，一次反例都没有。** 符号检验 p = (1/2)^42。

但比 p 值更值钱的是**效应随难度单调变大**（5.3 → 8.5 → 12.1）：
🪝 **剂量-反应关系是因果证据里最硬的一类** —— 若只是某种系统性偏差，
它没有理由跟着任务难度走。stage-2 只有单一效应量，这一批把它升级成了趋势。

**成本来自「工具的存在」而非「系统的催促」——复现**：
去掉催促但保留工具（nudge → tool）：+0.2 / +0.3 / −2.4 步，基本落在噪声里。

## 二、记忆轴：一个真的零结果（本批最重要的负面发现）

### 2.1 立项假设与结果

建 t13-t15 三道多轮题的理由写在提交里：**「让记忆层终于有机会产生收益」**。
stage-2 的 8 题全是单会话一次做完，记忆无用武之地，那个轴测出来必然是噪声。

结果：

```
关掉记忆的代价    老 8 题 -0.3    新 4 题 +1.2    多轮题 +0.3
                                                  ↑ 噪声底线 2 步（同配置 3 次重复的 min-max 中位数）
```

**在专门为记忆设计的多轮题上，关掉记忆只差 0.3 步。假设被自己的数据否掉。**

### 2.2 排除「记忆层坏了」这个可能

```
memory_injected 为真的比例
                老 8 题   新 4 题   多轮 3 题
mem_none          0%       0%         0%     ← 关了就是关了
mem_self          0%       0%       100%     ← 单轮没有上一轮可记；多轮 100% 注入
mem_official      0%       0%         0%     ← 官方档不自动注入，要模型自己调工具
```

机制完全正常。**这是真的零结果，不是坏了。**

### 2.3 为什么（一个不能证实但站得住的解释）

多轮题里，第二轮拿到的**不只是记忆**：

```
第一轮结束后，考场文件夹里留下两样东西
  ① .memory/      ← 只有 self / official 档才有
  ② 被改过的代码   ← 【所有档都有】，连 MEMORY_MODE=none 也有
```

以 t13 为例：第一轮改了 `schema.def`、重新生成了 `validators.py`。第二轮就算记忆全关，
打开文件夹照样看得见，读一下 `codegen.py` 就能重新推出「这是生成物」。

🪝 **这三道题测的不是「记不记得住一件不可能知道的事」，而是「要不要重新推一遍」。**
而重推的成本，在这个模型上小到淹没在噪声里。

**要让记忆轴真正说话，题目必须满足一个更强的条件：
第一轮习得的东西【不能从工作区里重新推导出来】。**
（例如：第一轮踩到一个只在特定输入下才出现的坑，第二轮换个工作区。）
这是 stage-4 的出题约束，记在 §六。

### 2.4 一条记下但不解释的观察

```
                     mem_self  mem_none      差    逐 trial
t13_codegen_quirk       24.0     18.7      -5.3   [-7, -4, -5]  ← 三次同向
t14_registry_convention 24.0     26.3      +2.3   [-1, 6, 2]    ← 噪声
t15_diagnose_then_fix   28.0     32.0      +4.0   [-7, 11, 8]   ← 噪声更大
```

t13 上**关掉记忆反而省 5.3 步，三次 trial 方向一致**。翻日志看工具分布：
`bash` 26 次 vs 16 次、`todo_write` 16 次 vs 12 次，而 `read_file` 两边都是 20 次
——记忆没有省下读文件，反而多出了 bash 调用。

**n=3、噪声底线 2 步，机制在日志里看不出来。记一笔，不编解释。**

## 三、难度：企业级 bug 没能撼动通过率天花板

### 3.1 一条被推翻的预测

stage-2 的 8 题 120/120 全过，当时判断「通过率这个指标已经饱和，
如果新题能把模型压到中间区间，这个指标就复活了」。

**没有。225/225 全过，天花板一点没动。**
四道刻意设计的企业级 bug（两 bug 互相掩盖 / 竞态+锁粒度 / 配置缓存+加载顺序 /
重试遇上不幂等）对 `composer-2.5-fast` 仍在能力范围内。

### 3.2 真正买到的是力气的量程

```
                 steps   token   耗时
老 8 题（单轮）    9.3     25k    51s
新 4 题（企业级）  14.1     45k    94s
新 3 题（多轮）    22.9     67k   140s
```

🪝 **通过率死了，effort 才是这个 bench 的判别指标。**
而这恰恰是消融实验想要的区间：题目落在「做得出，但费多少力气不一样」上，
臂之间的差异才不会被随机失败的噪声淹没。

📌 反过来说：**为消融服务的 bench，不该追求把模型压到 50% 通过率**。
昨天那句「通过率复活了才算成功」本身就是错的目标。

## 四、主干改动前后对照（白送的一次实验）

老 8 题在两批之间除主干外一切相同，于是构成对照。

```
臂             steps 前   steps 后     变化
mem_none         13.9      10.0      -3.9   ← 看着像大幅改善
mem_self         10.0      10.2      +0.2
mem_official     11.6      11.0      -0.6
todo_none         5.4       4.9      -0.5
todo_tool        11.0      10.5      -0.5
```

**但 -3.9 是假的。** 拆开看噪声：

```
批内「同配置同题 3 次重复」的 min-max 波动
  08-15 批   中位 2   最大 53   ← 有异常值
  08-16 批   中位 2   最大  9

t08 × mem_none 三次实际值
  08-15   [13, 14, 66]   ← 一次跑飞到 66 步
  08-16   [13, 14, 14]
```

n=3 的格子里出一个 66，均值就被抬高 17。**「主干改好了」是均值被异常值污染造成的错觉。**

🪝 **跨批比均值之前先看批内波动 —— 噪声底线不量，差异就无从解释。**

### 4.1 那个 66 步是什么（比 stage-2 记的更严重）

`STAGE2_NOTES.md` §3.3 把它记成「模型跑出考场读标准答案」。翻日志翻出完整链条：

```
t08 原卷真实存在的校验器     8 个
那次跑飞写出来的文件        48 个   ← 凭空发明了 40 个
```

发明出来的包括 `check_latitude` `check_longitude` `check_semantic_version`
`check_credit_card_len` `check_isbn_len` `check_ip4` `check_json_object`……
**题目里根本没有这些。**

真实链条：

```
幻觉出一整套校验器库（40 个不存在的文件）
        ↓
把自己绕晕
        ↓
掉头 cat solution/    ← 这是【逃生绳】，不是病因
        ↓
对齐、清掉多余文件、交卷
```

**泄漏是它从幻觉里爬出来的绳子。而 08-15 那次修复把绳子剪了。**

⚠️ **直接后果**：下次再掉进这个幻觉螺旋，没有逃生口——那一次会超时或交白卷。
本批没观察到跑飞，**不能算作「六处修改起效了」，只能算「尾部这次没被采样到」。**
要分清得专门设计（比如刻意诱发幻觉的题），不在当前预算内。

## 五、口径限制（讲结论时必须带上）

1. **单一模型**：全部结论只在 `grok-composer-2.5-fast` 上成立。
   弱基座上 todo 层的成本结构可能完全不同（Weng「弱基座 + 复杂 harness 可能负收益」）。
2. **n=3**：每格三次重复，噪声底线 2 步。**小于 2 步的差异不要讲。**
3. **通过率无区分度**：225/225，这个指标在本批不携带任何信息，
   所有结论都建立在 steps / token 上。
4. **多轮题与单轮题的 steps 不可直接比**（前者是两轮累计，`rounds` 字段已标注）。
5. **记忆轴的零结果只对「信息可从工作区重推」这类任务成立**，见 §2.3。

## 二之二、追加实验：专门为记忆轴造的题（t16），结论是「测不出」

批次 `runs/run_20260816_195303`，3 臂 × 3 trial × 1 题（t16）× 2 轮 = 18 次 agent 运行，439s。

### 2.2.1 为什么造这道题

§2.3 诊断出 t13-t15 的毛病：第二轮还能看见上一轮改过的代码，**重推只要读 2-3 个文件 ≈ 1-2 步**，
而噪声底线是 2 步。于是 t16 两头都改：

- **重推变贵**：三条不成文的规矩，而且**踩了①②报的是一字不差的同一句错误**
  （`LookupError: no handler serving 'refund_issued'`），连是哪条都分不出
- **线索清零**：新增 `reset_between_rounds` 标记，第二轮把代码恢复原样，只留 `.memory`

### 2.2.2 机制这次完全按设计工作了

`mem_self` 三次 `memory_injected` 全为 True，而且第一轮写下的记忆**正是那三条规矩**：

```
handler-contract.md        "module handler_{event} exposing handle(payload)
                            that returns a dict with status and detail"      ← 规矩①③
event-dispatcher-bootstrap "bootstrap.ENABLED is the source of truth"        ← 规矩②
```

**所以这次不能再用「设计废了」解释。**

### 2.2.3 结果

```
臂                三次步数        均值    臂内极差   token
mem_none        [23, 33, 40]    32.0      17      79k
mem_self        [31, 34, 37]    34.0       6      90k    (+11k, +14%)
mem_official    [31, 37, 44]    37.3      13     118k    (+39k, +49%)
```

**开记忆多花 2.0 步。** 但——

### 2.2.4 🔴 这次实验根本分辨不出 2 步

```
臂内标准差              6.0 步
n=3 时两臂之差的标准误    4.9 步
→ 只能分辨出【大于约 10 步】的差异
实测差异                 +2.0 步        ← 完全在噪声里
```

要把 2 步跟 0 分开，**每臂需要 72 次，共 288 次运行，约 12 小时**。
即使跑到 n=9（90 分钟）也只能分辨到 5.7 步，仍盖不住 2 步。

**⚖️ 裁定：不跑，就此收口。** 这个问题在可接受的成本内 settle 不了。

### 2.2.5 「测不出」本身是结论——两条轴的对比

| | 效应量 | n=3 够不够 | 结论 |
|---|---|---|---|
| **TODO 轴** | −5 到 −12 步 | **够**（配对 0↑/42↓） | 硬结论 |
| **记忆轴** | ±2 步 | **差得远**（要 72 次/臂） | 测不出 |

🪝 **大效应便宜就能测到，小效应在可行的样本量下根本测不到。**
而 agent 跑批的固有波动（臂内标准差 6 步）决定了这条线画在哪。

**📌 讲结论时的正确说法**：不是「记忆没用」，而是
**「我知道我的实验能分辨多大的差异，而这个效应在那条线以下」**。

### 2.2.6 唯一能说死的是成本

```
mem_self      +11k token (+14%)   3 次额外 LLM 调用：挑记忆 / 提取 / 合并
mem_official  +39k token (+49%)   模型自己调 memory 工具，全进主循环
```

方向一致、量级明确。→ **在这类任务上，记忆层是一笔确定的支出换不确定的回报。**
这就够做决定了，不需要把回报测准。

### 2.2.7 🔴 本次实验设计的两个错误（都是我的）

**① 门槛是拍脑袋定的。** 开跑前我写下「差 ≥5 步就算记忆有用」，
**从没算过 n=3 能不能分辨 5 步**——答案是不能，只能分辨 10 步。
🪝 **写下预期是好习惯，但预期里必须包含「我这个实验的分辨率是多少」，
   否则那个门槛只是个愿望。**

**② 把题做难，同时放大了效应和噪声。**

```
上一轮   效应太小（重推 2 步）        → 淹在噪声里（臂内标准差 ≈ 2 步）
这一轮   把题做难，效应变大了         → 但噪声从 2 步涨到 6 步
```

🪝 **提高任务难度可以放大效应，但它同时放大噪声——净收益不一定是正的。**
下次要提高信噪比，应优先想「怎么把噪声压下去」（配对、增加题数而非 trial 数、
固定随机性来源），而不是「怎么把效应做大」。

## 五之二、一条被裁掉的实验（2026-08-16，当事人裁定）

**观测**：225 次跑批里，27 个工具**只有 8 个被用过**，20 个一次都没用。
而 schema 每一轮都要发一遍：

```
schema 总量      11,958 字符 ≈ 2,989 token/轮
没用过的 20 个     8,301 字符 ≈ 2,075 token/轮   占 69%
按平均 6 轮 × 225 次 ≈ 白烧 2.8M token
```

**AI 提议**：开第三条消融轴 `TOOLS_MODE=full|lean`，测裁剪工具池的收益。

**⚖️ 当事人裁定：搁置，不做。** 理由：真实任务里就该给全部工具，token 这点消耗不值得省。

**📌 而且当事人指出了一个 AI 没说清的要害**：那 20 个工具没被用过，
**很可能是题目分布的问题，不是工具池的问题**——这 15 道题全是「小 Python 仓库里修 bug」，
本来就用不上 cron / worktree / 多 agent 协作 / MCP。
在这样的题库上跑出「裁剪有效」，只是在证明「用不上的东西可以不给」，**不构成通用结论**。
🪝 **一个变量在你的数据里没有变化，往往是因为你的数据不覆盖它，而不是因为它不重要。**

**唯一仍然悬着的一条**（记录备查，不影响本裁定）：
T19 综合验收在**弱基座**（`deepseek-v4-flash`）上实测到 27 个工具导致**输出质量退化**
（混入土耳其语/俄语、泄漏 `</think>`）。本批在 `composer-2.5-fast` 上 225/225 全过，
无任何退化迹象。→ **「给全部工具」这个结论与基座强弱有关，换弱模型需重新判断。**

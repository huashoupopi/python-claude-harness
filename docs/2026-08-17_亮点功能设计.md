## ① 动态工具子集:⚖️ 裁定不做(维持 2026-08-16 原判)

### 决策记录

- **原判**(`bench/STAGE3_NOTES.md` §五之二,2026-08-16,当事人裁定「搁置,不做」):①真实任务就该给全部工具,token 消耗不值得省;②225 次中 20 个工具未被用过很可能是**题库分布问题**(15 题全是小 Python 修 bug),在此题库上测出「裁剪有效」不构成通用结论。
- **08-17 复议**(当事人授权设计方裁定):**维持原判**。新增论据:
  1. **真实成本重估**:要回应「题库偏窄」,必须新造一组真会用到 skill/MCP/subagent 的评测题——这是整个方案中最贵且最难稳定的部分,总成本 3-4 晚而非 1-2 晚,与「数日后转入基础复习」的时间约束冲突。
  2. **缓存经济学大概率不利**:全量工具 schema 前缀每轮稳定,prompt cache 命中率高;动态子集使前缀逐任务变化,破坏缓存——「每轮省 2,989 token」可能是负收益。
  3. **叙事价值不减反增**:「评测显示 28 个工具只有 8 个被用过,AI 提议裁剪,被否——因为数据不覆盖 ≠ 不重要,且裁剪破坏前缀缓存」,这是判断力叙事,优于功能叙事。
- **数字口径(更正 v1 错误)**:schema 总量 11,958 字符 ≈ 2,989 token/轮;未用过的 20 个工具 ≈ 2,075 token/轮(69%);225 次共约 2.8M token。**输出质量退化只在弱基座(`deepseek-v4-flash`)T19 综合验收出现;`composer-2.5-fast` 上 225/225 无退化。**

### 替代动作(本轮执行):cached_tokens 补测(🟢 小型测量工程,二审更正性质)

- **前提事实**:当前 225 单元的 results **没有存 `cached_tokens`**(全库无该字段),所以这不是「不改代码的数据分析」。
- **步骤(定案)**:①扩展 usage 探针,读取 API 响应的 `prompt_tokens_details.cached_tokens` → ②写入 trace 与 results → ③补探针测试 → ④跑小样本(如 10 单元)实测,标注样本量。
- **结论边界(二审钉死)**:本测只能回答「**全量稳定工具前缀存在多少缓存收益**」;**不得**据此声称「定量证明动态子集是负收益」——没有实际跑过子集臂。产出措辞一律为「**为维持 08-16 原判补充证据**」。
- **产出**:命中率数字(含口径与样本量)写入 `bench/STAGE3_NOTES.md` §五之二「悬置条款」下;同步进 T23 系统设计复盘的决策叙事。
- **验收**:数字来自实测记录;⛔ 不许估算。**BACKLOG 处置(三审更正):把「`reasoning_tokens` / `cached_tokens` 未单独分析」拆成两条,本项只关闭 `cached_tokens` 一条;`reasoning_tokens` 保持挂账,不因本项划掉。**

## ② auto-compact:正确性审计与可观测性升级(不称新功能)

### 审计与修正点(审查列出,逐条处理)

1. **触发次序缺陷**:`snip_compact` 在 50 条消息时先硬裁中间历史,可能导致自动摘要**永远不触发**——审计五个机制(大结果落盘/snip/micro/proactive try_compact/reactive compact)的触发次序,明确各自阈值与职责边界,消除互相抢跑。
2. **`estimate_size()` 只是 `len(str(messages))`**,不是 token 估算 → **定案:本轮直接用「字符数/4」估算,trace 同时保留原始字符数;⛔ 不新增 tokenizer 依赖**。
3. **`CONTEXT_LIMIT=500000` 不是模型级配置** → 按模型配置化。
4. **「保留最近 N 轮」必须按完整 tool-call/tool-result 组切**,不得截断配对(截断即 API 400)。
5. **新增 compact 专用 trace 事件**(压缩前后 tokens、保留轮数、触发层),彩色视图可见。
6. **新增 REPL 用户命令 `/compact`**(现有仅模型可调用工具;REPL 只有裸 `input()` 和 `q`)。

### 验证方式(审查更正)

- ⛔ 不比「压缩 vs 不处理」——不处理只会得到 API 400,无信息量。
- ✅ 比「**当前四层策略 vs 改进策略**」,用**降低阈值的受控测试**触发压缩,验证:压缩后 agent 仍能引用早期关键信息(测试埋点)、无配对截断、trace 完整。

## ③ Checkpoint 回滚(拆包后再做;时间不足直接延期)

- **恢复**:REPL `/rewind` 列最近 checkpoints,选择恢复;恢复动作本身先快照(可撤销撤销)。
- **测试必须覆盖**:新建文件回滚(=删除)、二进制文件、恢复失败路径、路径越界防护。demo 只用 `edit_file` 场景。
